# 0.3.0 性能检查

使用相同本机 FTP 测试服务器、5,000 个小文件、1420×900 Electron 窗口。新进程和临时配置启动，各执行一次；连接完成后等待 500 ms，再采样 1.5 秒空闲区间。

| 指标 | 优化前 0.2.0 | 优化后 |
| --- | ---: | ---: |
| 渲染的文件行 | 5,000 | 25 |
| 页面 DOM 节点 | 35,161 | 353 |
| 从提交连接到目录可见 | 262 ms | 103 ms |
| 渲染器 JS heap 采样 | 16,100,000 B | 10,000,000 B |
| Electron 进程工作集总和 | 617,344 KiB | 507,360 KiB |
| 空闲 CPU 采样总和 | 0.20% | 0.25% |

页面节点减少是可重复验证的结构性改进。时间、堆内存和工作集为单次本机观测，受系统负载、缓存、GC、窗口和主题影响，不能作为所有设备上的性能保证。目录完成时间的轮询间隔为 100 ms。工作集由 `app.getAppMetrics()` 的各进程 `workingSetSize` 相加，可能重复计入共享内存，不等于应用独占物理内存。`performance.memory` 的堆值也可能经过取整。此次短时空闲 CPU 采样未显示下降，不据此宣称 CPU 降幅。

重现方式（会启动临时窗口和本机 FTP 端口）：

```bash
npm run build
node scripts/launch.cjs scripts/performance.cjs /private/tmp/trident-performance.json
```

脚本还验证大目录滚动到底部后能显示最后一项，并能回到首项。文件列表仍需接收和保留完整的服务器目录数据；本次主要优化 DOM、重复排序和传输进度引起的渲染开销，没有宣称服务器端分页。

终端另有单元与真实 UI 测试：小块合并保持字节和 UTF-8 顺序、256 KiB 水位附近暂停输入流并等待终端确认、关闭时清理定时器；真实 SSH 连续输出 20,000 行，验证完成标记、主题切换保留终端内容，以及切到后台后恢复输入。5000 行是回滚历史上限，不是输出传输上限。

主题与协议回归通过 `npm run test:ui` 执行，覆盖浅色/深色/跟随系统、配置落盘、FTP 文件操作、凭据加密及备份往返。所有服务器和数据都在本机测试环境中创建。
