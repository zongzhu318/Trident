# Proposal

## Why

批量上传或下载包含大量小文件时，当前实现逐文件串行执行，每个文件都要经历一次完整的协议往返（FTP 的 MLSD/SIZE/STOR、SFTP 的 open/stat/close），整体耗时近似单文件耗时之和，用户等待时间明显偏长。小文件场景的瓶颈是往返延迟而非带宽，因此需要在不改变单文件传输语义的前提下引入有界并发。

## What Changes

- 批量传输拆为「目录阶段」与「文件阶段」：先按父目录先于子目录的顺序创建全部目录（同层目录并发创建；SSH/SFTP 会话用一次远程 `mkdir -p` 创建整棵树，失败时回退逐目录创建），再用固定大小的工作池并发传输文件。
- SFTP 在同一条 SSH 连接上并发多个文件流，默认并发 4；平均不超过 1 MiB 的小文件批次提高到 16，降低往返延迟占比。FTP/FTPS 在传输期间额外建立控制连接池，默认并发 3，主连接保留用于浏览与控制。
- SFTP 上传不再为每个文件预先 `lstat`：独占创建在写入前失败后再确认同名冲突；FTP 的 STOR 会覆盖，仍保留上传前检查。
- 并发度按 `min(默认并发, 待传文件数)` 生效，单文件传输行为与当前完全一致；并发度以内部常量固定，本期不提供设置界面。
- FTP 连接池在传输开始时惰性建立，传输结束（完成、失败、停止）后关闭；建连失败（如服务器 421 连接数超限）时自动降级并发，全部失败则回退到主连接串行。
- 传输控制器改为聚合进度：同时跟踪多个在途文件，整体字节为「已完成字节 + 所有在途文件已传字节」之和；面板展示活动文件数与「并行 N 个文件」。
- 面板在建目录阶段展示目录进度，避免整棵树创建期间进度条停在 0%；运行时按最近数秒的聚合速率估算并展示预计剩余时间，速率未知、暂停或传输结束时不显示。
- 暂停 / 继续 / 停止作用于所有在途文件：暂停中止全部流并保留各自的续传偏移，继续按文件各自恢复，停止清理所有未完成内容。
- 首个文件失败时终止整批：记录首个错误、中止其余在途文件，并保持现有失败提示文案。
- 同名冲突弹窗改为单次询问：并发 worker 共享同一个弹窗结果，仍对整批应用「跳过」或「停止」。
- 新增并发度、连接池降级、并行暂停/停止/冲突的集成测试，并为协议测试服务器补充并发与连接数观测能力。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `remote-file-transfer`: 批量传输的执行模型由逐文件串行改为有界并发，进度、暂停/继续、停止、失败处理与冲突策略需要覆盖多个在途文件；单文件与目录语义保持不变。

## Impact

- 代码：`electron/main.cjs`（传输控制器、上传/下载执行流程、FTP 会话与连接池生命周期、剩余时间估算）、`electron/files.cjs`（池化客户端复用现有适配器、独占创建失败标记）、`electron/preload.cjs` 与 `src/types.ts`（传输状态新增并发与剩余时间字段）、`src/FileBrowser.tsx` 与 `src/styles.css`（并行状态、目录进度与剩余时间展示）。
- 测试：`tests/helpers/ftp-server.cjs` 与 SSH/SFTP 测试服务器增加在途传输计数、最大并发数与连接数统计；`tests/ssh.integration.test.cjs` 增加并发、暂停/继续、停止、冲突与降级用例；`scripts/smoke.cjs` 适当补充并行状态断言。
- 文档：`README.md` 与 `src/App.tsx` 帮助文本说明批量并发、FTP 连接数限制、目录进度与预计剩余时间。
- 兼容性：单文件传输、目录结构、文件名校验、20000 条目上限与现有 IPC 字段保持兼容；FTP 服务器若限制连接数，行为自动降级而不会导致传输失败。
