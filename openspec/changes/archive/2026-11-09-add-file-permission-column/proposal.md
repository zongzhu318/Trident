# Proposal

## Why

文件面板当前只在鼠标悬停行的 `title` 提示中展示权限，列表本身没有权限列。用户浏览远程目录时无法直接判断某个文件或目录是否可读、可写、可执行，排查「上传失败」「目录不可进入」等问题需要逐行悬停。后端在目录列表时已经返回权限信息（SFTP 为八进制 `mode`，FTP 为符号权限串），无需额外远程请求，因此可以直接在列表中呈现。

## What Changes

- 文件列表新增始终显示的「权限」列，位于名称与大小之间；每行展示 9 位符号权限（如 `rwxr-xr-x`），目录加 `d` 前缀（`drwxr-xr-x`），符号链接加 `l` 前缀，普通文件以 `-` 开头。
- 权限来源统一：SFTP 的八进制 `mode`（`0o777` 位）在应用内转换为符号形式并对不足三位的八进制补零；FTP/FTPS 已有的 `rwx` 拼接串直接使用。无法获取或无法识别时显示 `—`。
- 权限列使用等宽字体、固定宽度与右对齐；名称列保持弹性并在空间不足时省略。表头同步增加「权限」列标题，三列对齐。
- 权限信息完全来自当前目录列表结果，SHALL NOT 为每一行额外发起 `stat`/`lstat` 请求；刷新目录后与列表一起更新。
- 悬停 `title` 保留完整信息（名称、权限、修改时间、符号链接不可打开提示），与列内展示保持一致。
- 该列为只读展示，不提供 `chmod`、权限编辑或按权限筛选能力。

## Capabilities

### New Capabilities

- `remote-file-browser`: 定义文件面板远程目录列表的条目元数据展示行为，包括名称、类型、大小、修改时间与权限列的呈现与刷新一致性。

### Modified Capabilities

无。

## Impact

- 代码：`electron/files.cjs`（把 SFTP/FTP 的权限统一规范化为 9 位 `rwx` 符号串，缺失时返回空串）、`src/FileBrowser.tsx`（表头与行内权限单元格、类型前缀、`—` 占位、`title` 保持完整信息）、`src/styles.css`（三列表头与行的网格/宽度、等宽字体与名称省略）。
- 类型：`src/types.ts` 的 `RemoteFile.permissions` 语义由「八进制或 `rwx` 串」收紧为「9 位 `rwx` 符号串或空串」，无 IPC 字段增删。
- 测试：`tests/ssh.integration.test.cjs` 增加 SFTP 与 FTP 列表权限规范化断言（含 755/644/600、补零与未知情况）；`scripts/smoke.cjs` 断言权限列存在、目录前缀为 `d`、SFTP 与 FTP 行内容正确。
- 文档：`README.md` 与 `src/App.tsx` 帮助文本补充权限列说明。
- 兼容性：布局变化只影响文件面板列结构；现有选择、双击、上传下载、刷新、隐藏文件、虚拟列表与传输面板行为不变。若 `add-batch-download` 变更先落地，其新的多选行结构需保留同一权限单元格，两处改动需合并处理。
