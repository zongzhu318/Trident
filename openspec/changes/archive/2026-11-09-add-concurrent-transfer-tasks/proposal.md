# Proposal

## Why

当前同一会话同一时刻只允许一个文件传输：界面在传输期间锁住文件面板，主进程用会话级串行锁串行化所有文件操作。用户想下载多个文件或文件夹时必须逐个等待，传输期间也无法浏览、重命名、删除或新建目录，效率低且不符合常规文件管理器习惯。任务内的多文件并行已经具备，但任务之间仍被串行化；需要把并发边界从「单任务内多个文件」提升到「会话内多个任务」，同时让文件操作与传输互不阻塞。

## What Changes

- 去掉传输对文件面板的全局忙碌锁：传输期间浏览、新建目录、重命名、删除保持可用，用户可连续发起多个下载或上传。
- 同一会话允许同时运行多个传输任务；每个任务独立维护扫描、统计、进度、暂停/继续、停止与结束状态，控制操作按任务标识（`taskId`）路由且幂等。
- 传输面板由单任务进度改为任务列表：每条任务展示方向、名称、进度、状态、并行文件数、速率与预计剩余时间，以及结束汇总；支持逐任务暂停/继续/停止，并可清除已结束任务的记录（保留最近 30 条）。
- 资源模型改为会话级共享：SFTP 多任务共享同一通道和会话级流上限（小文件 16、其余 4）；FTP 多任务共享连接池（最多 3 条任务连接），主连接通过互斥锁继续服务浏览与控制；所有任务结束、失败或停止后关闭额外连接。
- 断线时终止该会话全部任务并清理未完成内容；单个任务失败或停止不影响其他任务与文件操作。
- 任务失败时在任务项中直接显示原因（扫描、本地写入、远程错误或“连接已断开”），失败记录保留到用户清除；单个任务的失败原因不会因后续发起新任务而被覆盖或丢失。
- 任务标题固定使用顶层文件/文件夹名：下载取远程条目名，上传取所选顶层名称（多选为“首项 等 N 项”），扫描阶段也显示该名称；当前处理的文件通过独立字段上报并在“当前文件”行展示，不会把文件夹任务的标题显示成最后处理的文件名。
- SFTP 服务端瞬时失败（`SSH_FX_FAILURE`）增加有界重试：单个文件读写退避后按已写入偏移续传，目录扫描（`readdir`）退避后重试列表；最多 2 次、150ms/300ms 退避，尊重暂停、停止与断线。FTP 不参与该重试。
- FTP 本地写入失败（目标目录被删除、磁盘已满等）只终止当前任务：先无错关闭数据连接、捕获 `ftp.handle` 的拒绝，避免关闭共享控制连接或产生未处理拒绝，浏览与其他任务保持可用。
- **BREAKING**（内部 IPC）：传输事件新增 `taskId`；暂停、继续、停止接口新增 `taskId` 参数。preload 透传参数，主进程在只有一个活动任务时保留兼容回退。
- 更新主 spec 中「传输期间禁用文件操作」「同一时刻最多一个传输」等约束，新增「多任务传输与控制状态一致性」「传输期间的文件操作」要求。
- 新增并发任务、断线清理、失败原因、瞬时失败重试、文件夹任务标题、FTP 连接池共享与传输中文件操作的集成测试和 UI smoke 用例。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `remote-file-transfer`: 同一会话由「单任务 + 全局串行」改为「多任务并发 + 任务级控制」，并明确传输期间文件操作可用、SFTP/FTP 传输资源在任务间共享与释放。

## Impact

- 代码：`electron/main.cjs`（任务模型、`taskId` 路由、稳定任务名称与失败原因、SFTP 信号量与瞬时失败重试、FTP 连接租约池与主连接互斥、断线清理）、`electron/files.cjs`（FTP 本地写入失败隔离）、`src/types.ts`（`Transfer` 的 `taskId`/`file`/`error` 与控制接口签名）、`src/SessionView.tsx`（按任务合并传输状态）、`src/FileBrowser.tsx` 与 `src/styles.css`（任务列表面板、标题与当前文件、失败原因、逐任务控制、传输期间操作可用）、`src/App.tsx` 与 `README.md`（帮助文案）。
- 测试：`tests/ssh.integration.test.cjs`（SFTP/FTP 多任务并发、传输中浏览/新建目录/重命名、失败原因、目录扫描与文件读取的瞬时失败重试、文件夹任务标题、连接数回落）、`scripts/smoke.cjs`（两个慢速下载并发、操作按钮保持可用、文件内容一致、失败原因与文件夹标题展示）。
- 兼容性：单文件传输、目录结构、路径校验、20000 条目上限、冲突策略与暂停续传语义保持不变；IPC 事件与控制签名变化需渲染层与 preload 同步更新。
- 资源：SFTP 总会话流数受上限约束；FTP 额外控制连接最多 3 条，任务全部结束后关闭。
