# SFTP 下载吞吐实机验收

## 环境

- 测试时间：2026-11-18
- 客户端：Apple M5，macOS 26.6（arm64），Node.js v24.22.1
- 链路：直连 `172.16.66.129:22`，局域网内，无跳板
- RTT（5 次 ping）：min/avg/max = 5.242 / 13.006 / 20.109 ms
- 服务端文件：`/root/ghidra_12.2_PUBLIC_20261016.zip`
  - 字节数：569,712,708 B（543.32 MiB）
  - SHA-256：`2c2cd776db3c1f6a097ba418922378ac3649cadd5e844a6f5f088ae628a7be67`

## 对比版本

| 版本 | 说明 |
| --- | --- |
| 旧版 | 本机已安装的 Trident 0.0.20；其 `app.asar` 内 `electron/files.cjs` 与仓库 HEAD `49e5bda` 逐字节一致，直接以该适配器作基线 |
| 优化版 | 仓库 HEAD `49e5bda` + 本变更未提交改动（64 KiB 分块、每文件 8 块窗口、会话 32 块预算、乱序暂存与按序写入） |
| 系统 SFTP | OpenSSH_10.3p1 `sftp` 客户端，同一账号与文件 |

## 协议

- 每个版本、每轮都完整下载同一远程文件到本地临时目录，下载完成后计算 SHA-256 并与服务端比对，随后删除本地副本。
- 正式测量前先由系统 SFTP 完整下载一次作为预热（不计入结果），确认链路与凭据可用。
- 旧版、优化版、系统 SFTP 各 3 次，共 9 次；轮次顺序依次为 `旧/优/系`、`优/系/旧`、`系/旧/优`，降低时段性网络波动对单一版本的系统性影响。
- 旧版与优化版直接用各自的下载适配器计时：建立 SSH 连接后，从调用 `download()` 到落盘完成，不含登录与建连。
- 系统 SFTP 通过 `expect` 驱动：登录提示结束后开始计时，`get` 返回后结束，`bye` 不计时。
- 测试期间未运行其他传输或大流量任务；每次测量使用独立连接。
- 指标：耗时取完整下载秒数；吞吐按 569,712,708 B / 耗时换算为 MiB/s；中位数取 3 次排序后的中间值。

## 验收结论

- 优化版中位吞吐 / 系统 SFTP 中位吞吐 = **1.06x（106%）**，高于 70% 门槛。
- 优化版中位吞吐 / 旧版中位吞吐 = **5.82x**，高于 3 倍门槛。
- 9 次下载字节数全部为 569,712,708 B，SHA-256 全部与服务端一致，无截短、重复或空洞。

## 未覆盖项

- **堡垒机路径未覆盖、未验证**：本次只验证了直连 `172.16.66.129:22`。本机保存的 `jumpserver` 条目（`jumpserver.zkwlzz.com:2222`）是独立主机，并非指向该地址的跳板路由，因此未做堡垒机路径的下载及暂停/继续检查，也未将其标记为已验证。
- 单文件窗口为 8、会话预算为 32 的取值仅在上述局域网链路上验证；高延迟或低带宽广域网链路的调优不在本次验收范围内。
