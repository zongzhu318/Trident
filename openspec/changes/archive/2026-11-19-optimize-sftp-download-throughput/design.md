# Design

## Context

问题与对照数据见 proposal.md。截图中的 13.2 MB/s 为瞬时显示，TCP 的 77.4 Mbps 是另一次测试的平均值，不能当作同一时刻的吞吐上限或验收基线。

- `electron/files.cjs:179` 使用 `sftp.createReadStream()`，未传读取参数。当前 ssh2 默认缓冲 64 KiB，读取完成后才推进下一轮；超出协议单次读取上限时还会串行拆分。
- `electron/main.cjs:976` 按文件数创建 worker。一个 ZIP 只有一个 worker，提高文件级并发常量不会增加其内部读取并发。
- `emitTransfer` 的 100 ms 节流只跳过通知，不等待，不作为本次优化对象。
- 当前下载通过追加写入 `.part` 文件，并用其实际长度作为暂停和瞬时失败后的续传偏移。并发读取必须继续保证临时文件是源文件的连续前缀。

## Goals / Non-Goals

**Goals:**

- 让单文件下载有多个读取请求同时在途，且读取、暂存、写入和取消均有明确边界。
- 同时保证单文件与会话资源有界，保持现有多任务和文件操作可用。
- 继续使用现有 files 适配器、控制器、统计和续传协议。

**Non-Goals:**

- 不改上传、FTP/FTPS、传输面板和凭据处理，不增加持久化配置或依赖。
- 不把某次测速值作为所有网络上的速度承诺，不采用自适应窗口或自动静默回退到旧下载路径。

## Decisions

### D1：在现有适配器中使用一个句柄进行有界预读

SFTP 下载打开一个只读句柄，使用公开的 `sftp.read` 提交不同偏移的数据块。初始参数为每块 64 KiB、每文件最多 8 个未消费块；少于一块的文件自然只产生一个读取。复用现有文件 worker，不增加 SSH 连接、SFTP 通道或文件句柄数量。

这不是简单增大 `highWaterMark`：当前库的超限拆包仍串行，较大的缓冲不等于多个请求同时在途。库自带 `fastGet` 可作性能参考，但不直接替换，因为需要继续控制暂停、取消、连续落盘和续传偏移。

### D2：连续写入与背压决定窗口释放

每个块记录源偏移和有效长度。响应可乱序返回，按偏移保存在有界窗口内；仅把连续的下一块按序交给本地写入流，并遵守背压。块预算覆盖“请求在途、响应暂存、正在写入”整个周期，待该块写入回调成功后再释放并调度下一块，避免慢速磁盘或首块延迟造成无限暂存。

进度只在写入回调成功后累计，预读到内存的数据不计入已传输字节。保留追加写入模式与完成后重命名，整个文件的数据及句柄关闭成功后才报告下载完成。

### D3：为每个会话设置共享预算

每个会话最多持有 32 个未消费块，每块不超过 64 KiB，总读取缓冲预算不超过 2 MiB；每文件仍不得超过 8 块。额度在分配块缓冲和发出请求之前申请，按 FIFO 唤醒等待者；会话预算覆盖该会话全部下载任务，已有文件流上限独立保留。

申请额度和本地背压等待都必须可取消。正常完成、错误、取消、断线均释放预算并唤醒等待者，迟到回调不得重复释放。预算绑定会话生命周期，不引入全局任务调度器。上述内存边界只涵盖下载器拥有的块缓冲，不包括库、TCP 和本地流本身的有限内部缓冲。

### D4：短读、结束与清理

- 短读按实际收到的长度推进，对当前块剩余区间继续读取；禁止把未填满缓冲写入文件。
- 以本次开始时取得的文件大小限定范围；空文件不发 READ。达到计划大小前收到 EOF 或零字节响应视为源文件截短，失败并按现有流程清理，防止死循环或伪装成功。额外增长的数据不在本次传输范围内；同长度原地修改不新增快照保证。
- 暂停、停止或错误时停止调度、移除额度等待者、丢弃未落盘块，中止本地流并尽力关闭本次句柄。已发出的单个 SFTP 请求不能独立撤回，回调应被接收并忽略，不得再写入或上报。
- 下载操作返回或抛错前等待本地流关闭，保证不会继续写入；旧尝试的迟到回调与新尝试隔离。暂停后的本地文件大小仍代表连续前缀，控制器从该大小重新读；预读但未写入的字节可以重新请求。
- 保留现有 `SSH_FX_FAILURE` 最多两次退避重试，不把其他协议错误一律降级或吞掉；正常路径关闭失败不得报告成功，清理失败不得覆盖最初错误。

### D5：用结构性验证和实机测速分别验收

扩展现有 SSH/SFTP 测试服务：可控延迟、乱序响应、短读、提前 EOF、指定读取失败以及当前/最大在途数。验证单个大文件确实存在多个 READ 同时在途，同时对照源数据验证完整内容或 SHA-256。验证窗口及会话预算上限、暂停后稳定、续传连续、停止后无迟到写入、一个任务取消不影响另一个任务。覆盖本地写入错误、断线和异常后的资源回收。

实机在相同电脑、服务器、连接路径和同一约 500 MiB 文件下，停止其他测试传输，分别对旧版、优化版和系统 SFTP 各做 3 次顺序完整下载。记录总字节、总耗时、平均吞吐、中位数、连接路径、版本与 SHA-256。目标为优化版中位吞吐至少达到同批系统 SFTP 的 70%，且至少是旧版的 3 倍。未达到则继续定位或记录阻塞原因，不能只凭并发计数宣告性能问题解决。直连用于主要验收；若具备已有堡垒机登录条件，再补一次该路径对照，不以修改其权限或配置为前提。

## Risks / Trade-offs

- 首块慢导致后续暂存 → 窗口与会话预算统计未消费块，写入后才释放。
- 并发放大服务器压力 → 每文件 8、会话 32 的内部上限；多任务测试验证公平与释放。
- 暂停后迟到响应污染续传 → 每次尝试隔离取消状态，写流关闭后才允许控制器重新测量偏移。
- 实际吞吐仍受 Wi-Fi、SSH 加密或服务器影响 → 使用同批完整文件对照，不承诺固定 MB/s。

## Migration Plan

无需数据迁移。先完成针对性验证和现有回归，再做实机对照；发布另行处理。若需回滚，恢复下载适配器及共享预算改动即可，临时文件格式和续传偏移协议不变。
